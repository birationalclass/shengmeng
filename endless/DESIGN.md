# 《无尽》设计与发布记录

## v152：分级成就、炮塔复演与折叠图鉴

- 成就 UI 不再逐条渲染底层升级记录，而是按遗物/规则族汇总为一条等级轨道。每张轨道卡固定显示 `LV.当前/上限`、当前累计或最高完成条件与下一目标；旧的 50 条难度成就、两组各 10 条击杀成就仍留在账号数据中用于迁移和自动补发。
- 六类炮塔各有一个终结者轨道和 50 级复演遗物：子弹炮对应“弹道复演核心”、激光炮对应“光束复演核心”、导弹炮对应“蜂群复演核心”、冰霜炮对应“零度复演核心”、电弧炮对应“雷脉复演核心”、支援炮塔对应“纳米复演核心”。难度等级使用 `majorIndex * 5 + minor`，因此行星 I / 行星 V / 恒星 I / 终焉奇点 V 分别对应 LV.1 / 5 / 6 / 50。
- 第 50 波通关时按 `state.stats.damage` 汇总整局归属伤害。所有并列最高且伤害大于 0 的炮塔共同完成终结者；来源“分段屏障”和全局生存卡“相位反冲”明确排除，避免非炮塔伤害被误归为支援输出。低难度重打不会降低等级。升级只写账号遗物档案，不改本局 `runRelicLevels`，所以下一局才生效。
- 复演概率为 `(10 + relicLevel) / 100`，LV.1 为 11%、LV.50 为 60%。五类攻击炮塔只在“杀戮成长”实际增加基础攻击后判定一次；支援只在“治疗成长”自然判定成功后再判定一次。复演直接追加同额数值，不调用原成长函数，因此不会递归。
- “微壁垒纪元”记录五段中任意单段的历史最高 `maxHp`，阈值从 `1e9` 起每级乘 10，至 `1e18` 共十级。遗物“壁垒原核”依次给新局五段初始总量固定 `+10` 至 `+1e10`；公式为 `INITIAL_BARRIER_TOTAL * (1 + barrierSeedLevel * 0.1) + originBonus`。旧“千万壁垒”仍按五段总上限 10m 独立解锁筑垒核心。
- 左上 HUD 新增返回部署页入口。操作先暂停并二次确认，只有 `saveRun(false)` 成功才进入初始菜单，取消后恢复原暂停状态。登录成功时调用最高解锁难度计算一次；`refreshDifficultyOptions` 在未认证阶段不再向下夹紧设置，也不会在玩家后来主动选择低难度时强制抬高。
- 图鉴所有分类、种类数与等级分母统一取 `!designRemoved` 的可获取目录。普通账号通过 `libraryDisplayLevels` 将每个基础卡压缩为一个卡面：已有等级显示最高级，未拥有显示 I；设计账号仍显示 `1..max` 全部卡面。等级统计仍按真实独立级别累计，不把多级卡错误视为只有一张。旧存档卡表会过滤废卡、合并重复项，并迁移八个旧冰霜 ID；旧 `shop.rate/crit/critDamage` 也由同一入口按最高等级合并，使部署页摘要与实际加载完全一致。

## v151：十级遗物、独立卡级与逐敌伤害档案

- 左上 HUD 将波次、时间、难度并列为三格；难度读取本局快照而非可编辑设置，确保进行中战局、读档与测试直达均显示实际生效等级。
- 难度轴扩展为十个大难度：行星、恒星、中子星、黑洞、星云、星团、星系、类星体、宇宙网、终焉奇点。每个大难度保留 I～V，共 50 个连续威胁阶；第 `n+1` 阶敌方生命、护盾、攻击和固定伤害仍为第 `n` 阶的 1.5 倍，数量与速度不套用指数倍率。
- 五件大难度遗物均为 10 级。每个大难度完成 I / II / III / IV / V 时，分别升级远域测距阵列、多重补给舱、军械基座、屏障晶种、脉冲节拍器。军械基座每级固定 +20 基础攻击、满级 +200；脉冲节拍器每级 +5% 基础攻速、满级 +50%；测距阵列从 10% 成长至 30%，但五张射程卡仍使用原有五档曲线。
- “群星战勋簿”按累计小怪击杀 1,000 起步、后续每级翻倍解锁至 LV.10；普通、分裂与召唤小怪全部计数，Boss 和奖励怪不计入。装备后每 100 个小怪固定进行一次 20% 判定，成功则把本局全局伤害永久提高当前遗物等级对应的 1%～10%。
- “悬赏回声信标”按累计任意星级奖励怪击杀 100 起步、后续每级翻倍解锁至 LV.10；装备后每 5 个奖励怪进行一次 10%～40% 判定，成功时生成一个与本次击杀相同星级的奖励怪。
- 新增 ★1 五级特殊卡“余辉演化”：10% / 13% / 16% / 20% / 25% 概率令本波常规四选一刚获得的卡牌再升一级。它不复制开局奖励、限时奖励、禁忌抄本选择，也不递归触发概率折射。
- 卡牌等级改为独立展示实体，稳定标识为 `baseId@level`。选牌、最近获取、开局手牌与图鉴都显示固定的 `卡名·I`、`卡名·II` 和该级效果；账号构筑与存档仍以基础卡 ID + 等级保存，避免破坏旧存档。
- 详细伤害统计按基础卡 ID 汇总，因此同系列所有等级只占一行；简易统计继续按炮塔汇总。目标筛选增加全部、BOSS、小怪，BOSS 模式在多首领波次选择具体实例并显示名称。日志格式升至 schema 3，每个敌人记录总伤害、炮塔类别、来源、直接/间接和卡牌系列五类数据。完整逐敌明细仅驻留当前会话并可下载；localStorage 续局存档剔除高基数明细、保留每波聚合与 Boss 生命周期，防止长局超出浏览器容量。
- “相位回充”从脱战恢复改为战斗中持续恢复。删除入口始终跟随当前所选账号显示：普通账号未登录时需先校验其 4 位口令，系统测试账号与设计账号则显示为不可删除，而不是隐藏按钮。

## v150：遗物军械、射程回调与终局直战

- 射程卡撤销 v149 的固定 +40 / +85 / +135 / +195 / +270 方案，恢复旧版 6% / 13% / 22% / 34% / 全屏进度。远域测距阵列继续在卡牌结果之后增加局内成长，最终统一封顶全屏；遗物不再以削弱卡牌为代价。
- “军械基座”共 5 级，由账号最高完成第 10 / 20 / 30 / 40 / 50 波逐级解锁。每级让新局所有攻击炮塔的固定基础攻击分别增加 20 / 40 / 60 / 80 / 100，随后才进入各炮塔基础攻击卡的百分比乘区。
- “脉冲节拍器”共 5 级，由累计击破 5 / 15 / 30 / 50 / 80 个终局首领逐级解锁。每级让新局所有攻击炮塔基础攻速提高 5% / 10% / 15% / 20% / 25%；仍保留激光最短 5 秒启动间隔等炮塔自身硬限制。
- 新遗物继续使用开局等级快照；旧账号登录时会依据已保存的最高波次和终局首领击破数补发成就，但效果只在下一局写入战局。测试账号自动装备满级遗物。
- 左侧战局面板新增测试账号专属的第 50 关 Boss 直战按钮。入口使用当前选择的难度、满级卡池、完整屏障和真实第 50 关终局 Boss 预算，不开启无敌；普通账号不可见，避免调试流程污染正式进度。

## v149：曝光、射程成长与后期首领压力

- 激光功能卡“曝光”不再提供易伤，而是削减敌方生命上限。主激光与折光子炮每次射击各只进行一次 30% 判定；成功后给首个有效目标添加 1 层，贯穿、反射和 0.1 秒持续伤害脉冲不会重复判定。曝光最多 5 层，卡牌 1～5 级时每层分别削减 1% / 2% / 3% / 4% / 5%，独立持续 2 / 2.75 / 3.5 / 4.25 / 5 秒；Boss 的单层降幅减半。施加时当前生命会被压到新的上限以内，层数到期只恢复上限，不产生治疗。满级“折光节点”把同时存活上限提高到 4 座，与主炮组成 5 个独立光源，使满层在正常玩法中可达。
- 激光新增三段短控成长：“迟滞棱镜·Ⅱ”每次射击只光锢首个命中 0.15 / 0.25 / 0.35 秒；“光压回卷·Ⅲ”每第 3 次射击回推首个非 Boss 命中 20 / 35 / 50 点，并光锢 0.35 / 0.55 / 0.75 秒；“分光囚笼·Ⅳ”要求“镜面反射”，在首脉冲中光锢反射段命中的每个敌人 0.55 / 0.9 秒，同一敌人每轮最多一次。Boss 不受回推，三种光锢的持续时间均减半。
- 五张进攻炮塔射程卡统一为 5 级，固定在各自基础射程上增加 40 / 85 / 135 / 195 / 270，最高级固定为 +270。对应前线子炮塔按自身继承比例使用主炮实际射程；激光一旦完成锁敌，当前光束仍贯穿到战场边缘。
- 四级遗物“远域测距阵列”分别由行星、恒星、中子星、黑洞难度的首次第 50 波通关解锁。每次击杀非 Boss、非限时猎物、非召唤物的普通小怪时，按遗物等级进行 10% / 13% / 16% / 20% 判定；成功后让该次击杀归属的攻击炮塔在本局永久获得 +1 射程。可识别来源归给对应炮塔，其他间接来源回退给本波伤害最高的攻击炮塔，分段屏障击杀不归属。成长按子弹、激光、导弹、冰霜、电弧分别记录并随战局存档，新局重置；遗物等级继续遵守开局快照，本局中途解锁只在下一局生效。
- 中子星 I（连续难度阶 10）起，Boss 进入第 2 / 3 / 4 阶段会施加“视界压缩”：炮塔射程分别降低 10% / 15% / 20%，持续 5 / 6 / 7 秒。黑洞 I（难度阶 15）起，各阶段压制再提高 5 个百分点、延长 1 秒，最高为 25%；同难度下所有 Boss 在保护结束后的有效战斗时间每满 10 秒再获得 10% 伤害倍率，最多叠至 ×2。黑洞首领只在完成入场并进入技能阶段后累计久战时间。
- 状态反馈与存档同步更新：大型核心 Boss 状态栏显示曝光层数、实际上限降幅、光锢剩余时间和“久战增压”倍率，普通恒星 Boss 的紧凑血条上方也显示久战倍率；战场底部显示视界压缩强度与倒计时，炮塔射程悬停显示遗物成长和压制。曝光独立计时层、各炮塔射程成长、Boss 战斗计时及剩余射程压制都会随战局保存。

## v148：跨局遗物与指数威胁阶

- 成就“千万壁垒”以单局五段屏障生命总上限 10m 为阈值，奖励遗物“筑垒核心”；该遗物从下一局开始让初始构筑直接拥有“治疗筑垒”1 级。
- 遗物采用战局快照。账号进度负责记录解锁和强化，本局只读取开局时保存的遗物等级，因此任何中途奖励都不会追溯改变当前构筑。
- 四个天体难度、每个五个威胁阶继续组成连续 0–19 阶；相邻阶的敌方战斗数值严格乘 1.5。生命、护盾、攻击、固定伤害与按最大生命派生的治疗共享该倍率。
- 数量、移动速度、技能冷却、概率和百分比伤害不套用指数倍率，避免最高阶的 2216.84 倍系数破坏性能或让百分比规则越界。
- 难度选择与遗物快照一同写入战局存档；载入和通关记录均使用开局快照。

## v90：密集敌潮性能与攻击卡成长

- 第 5 波这类高速密集潮的压力主要来自普通敌人的多层彗尾、逐单位阴影，以及炮塔在更新和绘制阶段重复索敌。现在以 32 / 48 个存活普通敌人为分界进行纯表现层 LOD，判定、血量、掉落与技能逻辑不降级。
- 炮塔索敌由“筛选后排序”改为一次扫描，并把瞄准坐标写入炮塔状态供绘制复用，避免敌人数与炮塔数相乘后产生不必要的临时数组与距离开方。
- 攻击炮塔的基础攻击与暴击伤害成长继续加强；攻速、暴击率保持不变。伤害型卡牌每次升级同时提供百分比攻击和固定攻击，固定值等于该卡星级。
- 数值结算顺序统一为：先合并炮塔初始攻击与所有固定攻击，再乘基础攻击提升系数，最后进入暴击、易伤、距离减伤与联动倍率。

```text
基础攻击 = (炮塔初始攻击 + Σ伤害卡等级对应固定攻击) × (1 + Σ基础攻击提升)
```

## 1. 项目边界

这是一个全新游戏，不继承《疆域争锋》的领地、据点、派兵、建筑或关卡内容。复用的只有已经验证过的设计与发布过程：先确认核心体验和负面反馈，再写规则原型，用真实浏览器连续游玩，最后同步到个人主页仓库并由 GitHub Pages 发布。

商业边界从第一天固定：无充值、无广告、无体力、无付费复活、无付费刷新、无局外战力售卖。账号只负责隔离存档和最佳纪录。

## 2. 核心体验

玩家从一门可靠的纯子弹主炮开始，在无限增长的敌潮中逐步组装整条防线。爽感来自高频命中、暴击、激光、爆炸、连锁与范围控制；挑战来自生命指数增长、单位数量增长、限时猎物和第 8 波后敌方远程反击。

```text
单子弹炮开局
  → 击杀并推进波次
  → 波次结束选牌
      ├─ 解锁一种新炮塔
      ├─ 强化已有流派
      ├─ 补充吸血或护盾
      └─ 承担代价换取更多未来选择
  → 从随机牌池获得全局基础属性
  → 应对更强敌潮与敌方炮火
  → 防线失守后结算，再次从零构筑
```

没有通关终点。能否持续下去取决于组合是否形成自我放大的输出、控制和续航循环，而不是把所有属性平均升级。

## 3. 竖屏与界面分区

战场坚持高度大于宽度，并把敌人由上向下推进的阅读方向作为主要视觉轴。

- 中央：只保留 Canvas 战场、必要的战斗反馈和暂停遮罩，不放常驻菜单。
- 左侧：账号、保存、载入、暂停、声音、设置、波次、时间、波次进度和炮塔优先级。
- 右侧：常驻 DPS/HPS 统计、卡牌图鉴和规则说明；宽屏时左右栏按浏览器扣除竖屏战场后的剩余空间弹性扩展，达到阅读上限后停止增长。
- 窄竖屏：中央战场保持完整，左右控制台收成边缘抽屉；打开一个抽屉会自动关闭另一个。
- DPS/HPS 与分色来源条常驻右侧；卡牌和说明从右侧展开，不再用居中窗口遮住整个战场。

这种布局既保证桌面浏览器的信息密度，也避免手机竖屏上菜单永久压住敌人和炮塔。

## 4. 炮塔结构

| 炮塔 | 获得方式 | 主要职责 |
|---|---|---|
| 子弹主炮 | 初始拥有 | 单体输出；并行弹、左右侧翼弹、最多四层穿透与燃烧弹 |
| 激光炮 | 卡牌部署 | 攻击范围只负责锁敌；每次射击的光束贯穿至战场边缘，镜面反射次数由卡牌等级限制，并可施加曝光与短时光锢 |
| 导弹炮 | 卡牌部署 | 高威力范围爆炸与燃烧，以较长充能时间换取爆发；并列发射架增加大型导弹，分裂弹头产生微型制导弹，目标消失后仍轰炸既定落点 |
| 冰霜炮 | 卡牌部署 | 单体冰弹起步，逐步解锁寒冰基站和冰冻网 |
| 电弧炮 | 卡牌部署 | 低直接伤害的大范围辅助炮，跳跃衰减明显，核心职责是给敌群叠加可累积的电离易伤 |
| 支援炮塔 | 卡牌部署 | 无攻击距离、全屏生效；用带冷却的治疗链、单体修复和护盾脉冲维持全域屏障与子炮塔 |

炮塔升级卡只有在对应炮塔部署后才成为合法候选；进入合法牌池后使用最近三次选择的类别疲劳权重，避免单一流派连续霸屏。

五种攻击炮塔各有一条前线子炮塔分支。主炮按射击次数把小型弹巢、折光节点、导弹仓、极寒哨站或电离信标部署到敌军附近。子炮塔生命和驻场时间有限；默认敌军保持向下推进，只攻击进入自身攻击范围的子炮塔，不会主动聚团绕路。获得`引力诱捕器`后，子炮塔才会在有限半径内改变敌军路线。`子炮塔轻质装甲`延长前线价值，支援分支的`前线维修蜂群`则为所有子炮塔恢复生命。

全域屏障就是本局唯一生命值：黄色护盾先吸收伤害，随后扣除蓝色玻璃屏障；屏障归零立即失败。支援炮塔必须在归零前通过`玻璃再生层`和`纳米修补节拍`维持修补量与修补速度，满修时还可触发后期火力超频。

五张专属射程卡统一限制为 5 级，沿用旧版 6% / 13% / 22% / 34% / 全屏成长曲线。对应前线小型炮塔按自身继承比例使用主炮实际射程，主炮通过“远域测距阵列”获得的局内成长会在卡牌射程之后额外相加并统一封顶全屏；支援炮塔没有攻击半径，始终按全屏技能逻辑选择最低耐久目标。

“远域测距阵列”是范围构筑的跨局入口而不是直接赠送固定射程。十大难度的 I 阶通关依次把遗物提升至 LV.1～LV.10；下一局开始，合格普通小怪死亡时以 10%～30% 判定，把 +1 射程归给该次击杀的攻击炮塔。可识别来源直接归属，其他间接来源回退给本波伤害最高的攻击炮塔；分段屏障、Boss、限时猎物、裂殖或黑洞产生的召唤物均不会刷取成长。已经获得的局内射程随存档保留，但新开战局重新从 0 计数。

“军械基座”和“脉冲节拍器”是开局军械遗物。前者提供 20～200 点固定基础攻击，进入所有基础攻击百分比之前；后者提供 5%～50% 基础攻速，与基础攻速卡相加后进入实际冷却计算。两者只影响子弹、激光、导弹、冰霜和电弧五种攻击炮塔，不改变支援炮塔的治疗制造节拍。

激光采用单向出射规则：从炮塔发出的第一段光束可以穿过己方屏障向外射击；一旦光束从战场边框折返，向下命中仍在运行的玻璃屏障时必须在圆弧法线方向再次反射，不能穿透进入炮塔区域。失效变灰的屏障不再参与反射。

## 5. 卡牌与组合

单卡分为全局、弹道、激光、导弹、冰霜、电弧、生存和功能方向。代表机制包括：

卡牌统计只读取未标记为 `designRemoved` 的可获取卡：子弹炮当前上限为 93 级；历史“奇点弹仓·III / IV / VI”共 6 级保留内部识别但不进入满卡预设、构筑计数、图鉴计数、遥测或新存档。

- `生命虹吸`：伤害转化为治疗，是高频、范围和持续伤害构筑的续航基础。
- `相位护盾`、`相位回充`：吸收第 8 波后的直接炮火并在战斗中持续恢复护盾。
- `破甲标记`：由子弹概率施加独立计时的易伤层，为处决和跨炮塔组合服务。
- `曝光`：由主激光与折光子炮按每次射击一次的 30% 判定削减生命上限，最多 5 层；Boss 降幅减半，层数到期不回血。
- `迟滞棱镜·Ⅱ / 光压回卷·Ⅲ / 分光囚笼·Ⅳ`：分别提供单目标稳定短控、每三轮一次的回推窗口和反射段群体光锢；Boss 只承受半时长光锢且不会被回推。
- `范围寒潮`、`脆化装甲`：扩大范围减速并让受控目标承受更多伤害。
- `禁忌洞见`：可叠加 5 级，每次正常选牌后分别以 20% / 28% / 35% / 43% / 50% 判定；触发时固定追加一次四选一并牺牲当前屏障生命 50%。追加选择设置不可递归标志，完成后回到触发前的开局、波末或限时奖励流程。
- `悬赏信号增幅`：三级分别在每 20 / 15 / 10 个敌人的节点进行一次独立 10% 判定，成功时把该节点的普通单位替换为奖励敌人，不影响每波固定限时猎物。
- `延时猎杀令 / 悬赏防御破译 / 悬赏生命削容`：分别对抗后期限时猎物的时限、减伤和生命压力；及时击杀仍会立即触发额外四选一。

组合牌只有在前置组件满足后出现：

| 组合 | 前置 | 循环作用 |

| 鲜血引擎 | 生命虹吸 + 禁忌洞见 | 低生命时吸血翻倍，溢出治疗转护盾 |
| 锁定熔解 | 破甲标记 + 曝光 | 目标同时具有易伤与曝光时，每层曝光令激光额外增伤 60%，最多 +300% |
| 等离子腐蚀 | 曝光 + 燃烧 | 燃烧对曝光目标每层额外增伤 16%，最多 +80% |

“特殊”标签覆盖禁忌洞见、悬赏对策和规则改写类卡牌，统一使用青—蓝—紫—玫红—金的五段柔和彩色玻璃背景，与单一炮塔色和普通功能紫色明确区分。

## 6. 选牌算法

每张卡有最大等级、最小出现波次、标签、前置条件和组合条件。候选权重遵循：

1. 只排除未满足前置、未到最小波次或已经满级的卡牌。
2. 刚选择类别的下一轮基础权重乘 0.38，两轮前乘 0.62，三轮前乘 0.82；同一张卡再分别乘 0.45 / 0.68 / 0.84。多炮塔组合牌会让它所代表的所有类别一起短暂冷却。
3. 所有候选权重在每个卡位重新归一化，被降低的概率自然补给其他类别；卡牌偏好的一个保底卡位不受类别疲劳取消。
4. 每次选择界面固定显示四张不同卡牌，并提供一次免费刷新；普通新局开场连续进行五轮四选一。
5. 限时猎物及时击杀后立即触发额外四选一；所有正常选牌都可以触发一次有生命代价的禁忌洞见，但禁忌追加选择不能再次触发自身。

限时猎物在奖励倒计时内不会沿固定直线推进，而是在战场上部的限定矩形区域选择随机目标点游荡。第 3 波出现 1 个，之后每 5 波增加 1 个、最多 5 个。基础时限从 34 秒起每波缩短 0.75 秒且不低于 8 秒；第 5 波后每波额外增加 8% 生命并逐步获得减伤。倒计时结束后恢复普通向下推进，既避免与前线子炮塔重叠聚团，也保留未及时击杀后的防线压力。

每一波在约 72% 的生成进度插入一颗大型 Boss；每 3 波固定切换为吸积盘黑洞，并在金冕、蓝白、紫极、暗红四套材质中循环。恒星用程序化日冕、耀斑、色球层纹理和暗斑表现，黑洞用事件视界、光子环、上下引力透镜弧与多层吸积盘表现，避免普通单位“只是换颜色和放大”的问题。

所有 Boss 出场后先获得 5 秒绝对保护：任何伤害、易伤、曝光、控制与破碎标记都不会生效，屏幕用黄色分段护盾环和实时倒计时明确反馈。保护结束后，普通减速、冻结和眩晕仍不会改变 Boss 的推进或攻击节奏；v149 的激光“光锢”是明确例外，可以短暂停止 Boss，持续时间按卡牌值减半。普通敌军在推进中发射可追踪目标位置的实体弹幕；恒星周期释放全场辐射环；黑洞使用 1.25 秒聚焦预警后发射伽马射线。

第 3 波起，敌军池加入裂殖增生舰。母体被击败后会生成 2～4 枚高速裂殖尖晶，生成物计入本波总目标和结算数量。该压力专门要求导弹炮承担 AOE：子母弹舱提高到 45% 起始半径、饱和火力每 3 轮触发，分裂弹优先寻找局部密度最高的区域；三张组件组成“裂群清算协议”后，对裂殖家族提高 35% 半径与伤害并触发连锁殉爆。

中子星 I 起，所有 Boss 在跨入第 2 / 3 / 4 阶段时分别触发 10% / 15% / 20% 的射程压制，持续 5 / 6 / 7 秒。黑洞难度把对应效果提高到 15% / 20% / 25% 和 6 / 7 / 8 秒，并让保护结束后的 Boss 每战斗 10 秒增加 10% 伤害倍率、最高 ×2；Boss 状态栏和战场底部必须持续显示倍率、压制强度与剩余时间，避免把高难度压力误读为炮塔失效。

Boss 的控制边界因此按来源区分：普通减速、冻结和眩晕继续无效，激光“光锢”按半时长生效；易伤、曝光、燃烧、寒冰/火焰破碎与直接伤害均保留。黑洞仍不响应电离诱引或子炮塔嘲讽，镜面反射次数也始终受卡牌等级限制。

选牌按钮先关闭遮罩，再在下一帧应用卡牌，避免选卡时同时触发大量 DOM 与 Canvas 更新造成卡顿。

## 7. 全局属性卡与战斗统计

金币和军械商店已经移除。原本可购买的全炮塔基础攻击力、暴击率、暴击伤害和攻击速度分别改为 `全局火力校准`、`弱点校准`、`致命载荷`、`全域超频`，与其他卡牌一起等概率进入合法牌池。

DPS 面板参考团队副本伤害统计的阅读方式：

- 简易模式按六座炮塔汇总；详细模式只按基础卡牌系列合并，卡牌等级不会拆成多行。
- “全部 / BOSS / 小怪”筛选位于简易与详细按钮下方；多 Boss 波次按实例选择并把 Boss 名称写入面板标题。
- 每个敌人的日志独立记录总伤害、炮塔类别、具体来源、直接/间接伤害与卡牌系列伤害。
- 显示总伤害、最近 5 秒滚动窗口即时 DPS、总治疗、即时 HPS 与峰值 DPS；统计每 0.2 秒更新并以 24% 插值连续追近窗口结果，无攻击时保留每个来源上一次非零即时值。
- 大于等于 1000 的总量、DPS/HPS 与伤害飘字采用 `k / m / b / t / q` 逐级缩写；来源条的标题保留未缩写精确值。
- 易伤造成的额外伤害按标记来源权重归入提供易伤的炮塔；跨塔热震爆炸则在冰霜炮和导弹炮之间等分。
- 吸血、维修、护盾相关治疗单独记录，不混进伤害。
- 存档保留累计伤害和治疗，短时窗口在加载后重新统计。

## 8. 账号和存档流程

```text
首次进入 → 创建本机账号与 4 位口令 → 新局
再次进入 → 默认定位上次账号 → 校验口令 → 显示上次记录
                                      ├─ 加载存档
                                      ├─ 从头重开
                                      └─ 从最高已清波次 n 的 n-5 附近快速部署
```

- 口令使用账号随机 ID 加盐后计算 SHA-256，只保存摘要。
- 存档覆盖波次、敌人、炮塔、冷却、卡牌、生命、护盾、计时和统计累计值；v149 额外明确保留曝光独立计时层、Boss 久战计时、各炮塔局内射程成长和正在生效的射程压制，旧存档的军械等级仍会一次性迁移为对应卡牌等级。
- 存档同时保留屏障启停状态与场上子炮塔，加载后不会绕过“修满才重启”的规则。
- 每 10 秒、波次开始、选牌、切后台和关闭页面前自动保存，也可以手动保存；失去窗口焦点只触发存档，不改变暂停状态。
- 普通新开局先直接授予 3 张互不重复的随机非质变卡牌（包含稀有卡池），再进行 5 轮连续四选一。快速部署仍按跳过的已清波次数、预计奖励敌人出现次数、基础 5 轮与每跳过 5 波额外 1 轮计算；全自动随机部署在同一结果上再额外获得 8 张合法卡牌，初始 3 张只计入一次。
- 右侧卡牌偏好是独立设置：可选择六种炮塔之一或“特殊规则”，每次四选一先锁定一张对应标签的合法未满级卡牌，再随机填满其余三张；偏好牌池暂时无合法卡时不生成无效或满级卡。按钮数字显示该标签在本局的累计卡牌等级。
- 内置本地“测试账号”，口令为 `1111`。该账号显示黑洞直测入口，可在第 5 波用全炮塔基准构筑随机生成四色黑洞，专门用于视觉与性能回归。
- 当前静态版使用 `localStorage`；未来接入云存档时可以保留界面，仅替换存储层。

## 9. 性能设计

- Canvas 像素比上限设为 1.35，避免高分屏竖屏画布产生不必要的填充压力。
- 战斗跟随浏览器 RAF 逐帧绘制；这避免 144 Hz 屏幕使用简单 60 FPS 时间门限时退化为约 48 FPS 的不均匀节奏。暂停、登录和选牌状态降低到约 18 FPS，逻辑更新仍与绘制解耦。
- 黑洞采用专业游戏常见的分层 Flipbook 管线：`v35-030-wide-zoom` 的 WebGL2 光路与体积云代码是唯一母版；捕获模式由合成着色器直接计算 Alpha，在页面内部降采样到 384×216 后输出像素数据，不通过页面截图。事件视界由 Canvas 程序化绘制为不透明黑色，四色 48 相位 WebP 负责吸积盘与透镜云层，左右光子环、受击闪光和烟消云散独立叠加。游戏默认 9.6 秒一周并混合相邻帧，速度较上一版减半但画面连续；常规战斗最多解码两套色系并提前预热下一种首领色系。
- HUD 每 0.18 秒更新，统计面板每 0.6 秒更新，不在每帧重建 DOM。
- 音乐使用 `preload="metadata"`，避免 14 首 OGG 阻塞口令输入；曲目在上一首结束后才加载下一首。
- 毛玻璃模糊只用于暂停中的选牌界面，不进入每帧 Canvas 战斗绘制。
- 测试账号提供第 5 波与第 40 波满卡无敌压力模式：双方数值无敌但所有战斗系统照常工作，敌军碰到屏障才消失；隐藏遥测同时记录 RAF 间隔、更新/绘制耗时、敌军/弹道/粒子数量、屏障生命和卡牌总等级。
- 一星基础数值卡在四选一卡面直接显示真实的“当前值 → 升级后值”。攻击按“初始值 + 固定值”后再乘基础提升系数，其他属性使用各自实际公式；显示统一取整数并复用 `k / m / b` 紧凑单位。

实际浏览器验收中，4 位口令填充约 20 毫秒，选牌至进入下一波约 280 毫秒。

## 10. 音乐设计

当前游戏按参考歌单顺序播放用户提供的 14 首 Melodysheep OGG：从 `Sun Mother` 开始，随后依次为 `The Somnium`、`Ether`、`Wither Away`、`Afterlife`、`Mesa`、`Subterranean`、`The Long Sleep`、`Black Desert`、`Hawking's Waltz`、`Oceans of Time`、`The Rising Dawn Bellows Like Thunder`、`City of Ghosts`、`Passage`。末曲结束后从头循环，设置中可改为不连续重复同一首的随机播放。

## 11. 验收与 GitHub Pages 发布

每次发布按以下顺序执行：

1. `node --check game.js` 检查语法。
2. 比对 HTML 中的 `id` 与 JavaScript 查询，防止界面元素漏接。
3. 在真实浏览器完成登录、新局、选牌、炮塔解锁、图鉴、DPS、屏障修补、保存、刷新和加载流程。
4. 在宽屏检查左右控制台，在窄竖屏检查左右抽屉。
5. 把 `index.html`、`styles.css`、`game.js`、文档、音乐和生成脚本同步到个人主页仓库的 `endless/` 目录。
6. 执行 `git diff --check`，提交并推送 `main`。
7. 等待 GitHub Actions 的 Pages 工作流成功，再访问线上地址做一次冒烟测试。

项目无构建步骤和第三方运行依赖，因此 GitHub Pages 可以直接托管。
