# 《无尽》设计与发布记录

## 1. 项目边界

这是一个全新游戏，不继承《疆域争锋》的领地、据点、派兵、建筑或关卡内容。复用的只有已经验证过的设计与发布过程：先确认核心体验和负面反馈，再写规则原型，用真实浏览器连续游玩，最后同步到个人主页仓库并由 GitHub Pages 发布。

商业边界从第一天固定：无充值、无广告、无体力、无付费复活、无付费刷新、无局外战力售卖。账号只负责隔离存档和最佳纪录。

## 2. 核心体验

玩家从一门可靠的纯子弹主炮开始，在无限增长的敌潮中逐步组装整条防线。爽感来自高频命中、暴击、激光、爆炸、连锁与范围控制；挑战来自生命指数增长、单位数量增长、限时猎物和第 8 波后敌方远程反击。

```text
单子弹炮开局
  → 击杀并获得金币
  → 波次结束选牌
      ├─ 解锁一种新炮塔
      ├─ 强化已有流派
      ├─ 补充吸血或护盾
      └─ 承担代价换取更多未来选择
  → 用金币强化全局基础属性
  → 应对更强敌潮与敌方炮火
  → 防线失守后结算，再次从零构筑
```

没有通关终点。能否持续下去取决于组合是否形成自我放大的输出、控制和续航循环，而不是把所有属性平均升级。

## 3. 竖屏与界面分区

战场坚持高度大于宽度，并把敌人由上向下推进的阅读方向作为主要视觉轴。

- 中央：只保留 Canvas 战场、必要的战斗反馈和暂停遮罩，不放常驻菜单。
- 左侧：账号、保存、载入、暂停、声音、设置、波次、时间、金币、DPS、生命、护盾、波次进度和炮塔优先级。
- 右侧：常驻 DPS/HPS 统计、卡牌图鉴、军械商店和规则说明。
- 窄竖屏：中央战场保持完整，左右控制台收成边缘抽屉；打开一个抽屉会自动关闭另一个。
- DPS/HPS 与分色来源条常驻右侧；卡牌、军械和说明从右侧展开，不再用居中窗口遮住整个战场。

这种布局既保证桌面浏览器的信息密度，也避免手机竖屏上菜单永久压住敌人和炮塔。

## 4. 炮塔结构

| 炮塔 | 获得方式 | 主要职责 |
|---|---|---|
| 子弹主炮 | 初始拥有 | 稳定单体、穿透、分裂、暴击、易伤 |
| 激光炮 | 卡牌部署 | 高频持续输出、叠加易伤、熔解高生命目标 |
| 导弹炮 | 卡牌部署 | 范围爆炸、燃烧、处理密集敌群 |
| 冰霜炮 | 卡牌部署 | 范围减速、脆化、为碎裂组合创造条件 |
| 电弧炮 | 卡牌部署 | 连锁跳跃、眩晕、全场雷击 |

炮塔升级卡只有在对应炮塔部署后才进入高权重候选，减少未解锁分支污染牌池。

## 5. 卡牌与组合

单卡分为弹道、激光、导弹、冰霜、电弧、生存、经济和功能方向。代表机制包括：

- `生命虹吸`：伤害转化为治疗，是高频、范围和持续伤害构筑的续航基础。
- `相位护盾`、`护盾再生`：吸收第 8 波后的直接炮火并提供脱战恢复。
- `破甲标记`、`熔甲光束`：施加易伤，为处决和激光组合服务。
- `范围寒潮`、`脆化装甲`：扩大范围减速并让受控目标承受更多伤害。
- `禁忌洞见`：立刻牺牲当前生命值 50%，永久增加以后每次三选一的刷新次数。
- `猎杀情报`：强化限时目标的金币与选牌奖励。

组合牌只有在前置组件满足后出现：

| 组合 | 前置 | 循环作用 |
|---|---|---|
| 鲜血引擎 | 生命虹吸 + 禁忌洞见 | 低生命时吸血翻倍，溢出治疗转护盾 |
| 锁定熔解 | 激光炮 + 熔甲光束 | 激光攻击易伤目标时持续增伤 |
| 冷热战斗部 | 导弹炮 + 范围减速 | 导弹命中减速目标时造成最大生命伤害 |
| 范围碎裂 | 范围寒潮 + 脆化装甲 | 减速敌人死亡后范围爆裂并传播减速 |
| 风暴阵列 | 电弧炮 + 增殖电弧 | 累积电弧命中后触发全场雷击 |
| 不落壁垒 | 相位护盾 + 护盾再生 | 扩大护盾，满盾时提高全炮塔伤害 |

## 6. 选牌算法

每张卡有最大等级、最小出现波次、标签、前置条件和组合条件。候选权重遵循：

1. 已拥有且未满级的卡提高权重，保证主流派能继续成长。
2. 与当前高频标签相同的卡提高权重。
3. 前置已经满足的组合牌获得最高额外权重。
4. 未部署炮塔的解锁牌在早期保持保底位置。
5. 每波可免费重抽一次，不存在付费刷新。
6. 选牌始终固定为三选一；限时猎物和禁忌洞见增加刷新次数，但不会直接赠送战力。

选牌按钮先关闭遮罩，再在下一帧应用卡牌，避免选卡时同时触发大量 DOM 与 Canvas 更新造成卡顿。

## 7. 金币与战斗统计

金币只在本局生效，购买全炮塔基础攻击力、暴击率、暴击伤害和攻击速度。价格随等级上升，形成“现在买基础属性”与“为后续高价升级留币”的选择。

DPS 面板参考团队副本伤害统计的阅读方式：

- 每种伤害来源有固定颜色、总量、占比和条形长度。
- 显示总伤害、最近 10 秒 DPS、总治疗、最近 10 秒 HPS 与峰值 DPS。
- 吸血、维修、护盾相关治疗单独记录，不混进伤害。
- 存档保留累计伤害和治疗，短时窗口在加载后重新统计。

## 8. 账号和存档流程

```text
首次进入 → 创建本机账号与 4 位口令 → 新局
再次进入 → 默认定位上次账号 → 校验口令 → 显示上次记录
                                      ├─ 加载存档
                                      └─ 放弃并重开
```

- 口令使用账号随机 ID 加盐后计算 SHA-256，只保存摘要。
- 存档覆盖波次、敌人、炮塔、冷却、卡牌、金币、商店升级、生命、护盾、计时和统计累计值。
- 每 8 秒、波次开始、选牌、切后台和关闭页面前自动保存，也可以手动保存。
- 当前静态版使用 `localStorage`；未来接入云存档时可以保留界面，仅替换存储层。

## 9. 性能设计

- Canvas 像素比上限设为 1.35，避免高分屏竖屏画布产生不必要的填充压力。
- 战斗时 60 FPS；暂停、登录和选牌状态降低到约 18 FPS。
- HUD 每 0.18 秒更新，统计面板每 0.6 秒更新，不在每帧重建 DOM。
- 音乐使用 `preload="metadata"`，避免 14 首 OGG 阻塞口令输入；曲目在上一首结束后才加载下一首。
- 不使用高成本的实时背景模糊。

实际浏览器验收中，4 位口令填充约 20 毫秒，选牌至进入下一波约 280 毫秒。

## 10. 音乐设计

当前游戏按参考歌单顺序播放用户提供的 14 首 Melodysheep OGG：从 `Sun Mother` 开始，随后依次为 `The Somnium`、`Ether`、`Wither Away`、`Afterlife`、`Mesa`、`Subterranean`、`The Long Sleep`、`Black Desert`、`Hawking's Waltz`、`Oceans of Time`、`The Rising Dawn Bellows Like Thunder`、`City of Ghosts`、`Passage`。末曲结束后从头循环，设置中可改为不连续重复同一首的随机播放。

## 11. 验收与 GitHub Pages 发布

每次发布按以下顺序执行：

1. `node --check game.js` 检查语法。
2. 比对 HTML 中的 `id` 与 JavaScript 查询，防止界面元素漏接。
3. 在真实浏览器完成登录、新局、选牌、炮塔解锁、图鉴、DPS、购买、保存、刷新和加载流程。
4. 在宽屏检查左右控制台，在窄竖屏检查左右抽屉。
5. 把 `index.html`、`styles.css`、`game.js`、文档、音乐和生成脚本同步到个人主页仓库的 `endless/` 目录。
6. 执行 `git diff --check`，提交并推送 `main`。
7. 等待 GitHub Actions 的 Pages 工作流成功，再访问线上地址做一次冒烟测试。

项目无构建步骤和第三方运行依赖，因此 GitHub Pages 可以直接托管。
