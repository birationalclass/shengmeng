# 《无尽》设计说明

## 1. 项目边界

《无尽》是一个全新的无尽防线游戏，不继承《疆域争锋》的领地、据点、派兵、建筑或关卡内容。复用的是上一项目已经验证过的工作方法：

1. 先研究同类产品与玩家负面反馈；
2. 把核心循环写成可验证的规则；
3. 先做零依赖、可直接运行的纵切原型；
4. 用真实浏览器验证开局、战斗、选牌、响应式布局和错误日志；
5. 最后接入个人主页的 GitHub Pages 发布流程。

## 2. 公开资料研究

研究对象是《我的防线》的公开介绍与玩家反馈，而不是复制其美术、数值、关卡或代码。

- App Store 的官方描述确认了其核心卖点：多炮塔构筑、针对敌人属性调整阵容、Roguelike 随机升级和成长反馈。
- TapTap 与 App Store 评论集中暴露了几个问题：起始炮台偏弱、多个炮台会污染升级选项、主体武器没有稳定保底、组合词条出现过少，以及付费成长影响体验。
- 《无尽》针对这些问题采用“局内完整、局外归零”的结构：所有内容开局可用，不售卖战力，不设置体力、广告复活、抽卡或付费刷新。

参考：

- https://apps.apple.com/cn/app/id6753862817
- https://www.taptap.cn/app/737040/all-info
- https://www.taptap.cn/app/737040/topic

## 3. 核心循环

```text
选择初始武装
    ↓
五炮台自动歼敌 ──→ 点击集火处理高威胁目标
    ↓                         ↓
积累极限火力 ─────────→ 手动释放爆发
    ↓
清空当前波次
    ↓
三选一卡 / 免费刷新一次
    ↓
强化已有流派或点亮跨系组合
    ↓
更高数量、生命、速度与特殊敌人
```

没有通关终点。失败时结算账号最佳纪录并结束当前存档；玩家可以再次从零开始。

## 4. 选牌反污染机制

每张卡有标签、前置条件、最低出现波次和最大等级。生成三张候选时采用以下权重：

- 已拥有且未满级：高权重，保证主流派能够继续成长；
- 与当前高频标签相同：按已有标签数量增加权重；
- 前置条件已满足的组合卡：最高额外权重；
- 未拥有的发现卡：至少保留一个探索位置；
- 传说级风险卡：延后出现并轻微降低权重。

三张卡因此形成“延续构筑 + 相关组件 + 新可能性”的结构。每波另有一次免费刷新，不存在付费刷新。

## 5. 六条组合回路

| 组合 | 组件 | 作用 | 解决的问题 |
|---|---|---|---|
| 超导风暴 | 雷 + 霜 | 电弧扩散寒霜，寒霜反增雷伤 | 控制与群伤互相放大 |
| 等离子链 | 雷 + 火 | 电弧引爆剩余灼烧 | 把持续伤害转成爆发 |
| 冷热震荡 | 霜 + 火 | 首次叠齐状态造成最大生命伤害 | 处理重甲和首领 |
| 雷暴核心 | 雷 + 弹道 | 高频触发全场轰击 | 把攻速转成全屏清场 |
| 绝对零度 | 霜 + 暴击 | 暴击冻结，冻结增强碎裂 | 建立控场连锁反应 |
| 余烬重生 | 火 + 生存 | 灼烧击杀修复屏障并点燃全场 | 把输出转化为长期续航 |

单系卡负责建立稳定输出，双系组合负责突破无限成长的数值压力。玩家不能靠平均升级长期生存，必须形成至少一个自我放大的循环。

## 6. 爽感与挑战

爽感来自高频命中、暴击数字、连斩倍率、电弧、碎裂、灼烧扩散、屏幕震动和“极限火力”的手动爆发。挑战来自：

- 敌人数量随波次近似线性加幂增长；
- 生命值按指数增长，并在高波次追加线性修正；
- 精英每 5 波出现，首领每 10 波出现；
- 疾行、重甲、护盾、裂殖等单位要求不同处理方式；
- 集火和极限火力都有时机成本，不能持续覆盖。

## 7. 音乐设计：《终线脉冲》

背景音乐是一首 84 BPM、D 小调倾向的原创四段循环。它不使用持续白噪声、高频踩镲或密集鼓组，避免与炮火音效争抢听觉空间：

- 低频三角波负责稳定的四拍脉冲，像防线持续运转的能源核心；
- 每半小节仅出现一次柔和电子底鼓，提供射击游戏所需的推进感；
- 正弦和弦以慢起音铺底，给无尽星潮留下空间和压迫感；
- 稀疏高音脉冲模拟雷达与火控确认，不覆盖真实命中反馈；
- 随波次升高逐渐打开低通滤波器并增加少量切分音；
- “极限火力”期间短暂加入更快的高频脉冲，结束后自动退回克制层次；
- 暂停、选牌和账号界面只保留约 14% 的环境强度，战斗恢复后再平滑抬升。

音乐由 Web Audio 实时合成，没有外部采样和版权素材；现有声音按钮会同时平滑控制音乐与音效。

## 8. 账号与存档流程

为了让“回到游戏”成为无尽模式的一部分，入口采用先认证、后选局的顺序：

```text
首次进入 → 创建本机账号与 4 位口令 → 选择初始武装
再次进入 → 默认定位上次登录账号 → 校验口令 → 展示上次存档
                                              ├─ 加载存档继续
                                              └─ 放弃存档重新来过
```

- 账号、口令摘要、最佳纪录和存档均按账号隔离；
- 口令使用账号随机 ID 加盐后进行 SHA-256 摘要，不保存明文；
- 存档覆盖战斗时钟、波次、敌人、炮台冷却、卡牌、组合、屏障、评分与主动技能状态；
- 自动保存发生在每 8 秒、每波开始、选牌界面、切后台和离开页面前；
- 顶部提供显式“保存”按钮，玩家可以随时建立最新续玩点；
- 游戏失败会清理本局续玩点，但保留该账号最佳纪录；
- 纯静态版使用浏览器 `localStorage`，不承诺跨设备同步。将来接云存档时可保持相同界面，只替换账户仓库层。

## 9. 技术结构

- `index.html`：游戏界面、账号、开局/续玩、选牌、帮助和结算结构；
- `styles.css`：桌面与移动端响应式视觉；
- `game.js`：Canvas 渲染、战斗更新、敌人、炮台、卡牌、组合、账号与本地存档；
- 无第三方运行依赖；
- 不需要构建步骤，适合直接部署 GitHub Pages。
